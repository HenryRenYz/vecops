# vecops 编译时间与 DataAccess 健壮性重构计划

## 背景与目标（本轮会话实测结论）

- LayerNormTest 单 TU：gcc 244s / clang 94s；根因是 256 个 dtype 组合 × 每 combo ~3.5 万行优化前 IR（其中约一半是选项解析/转发体操），全部强制内联后由优化器咀嚼删除 98%。
- 变量 variadic 路径实测代价：fold 通用路径 gcc 455s / 内存 12.4GB、实例化 13,204→22,208（特化分支保留，不动）。
- DataAccess.h（d1ac022 重构引入）transform 分块路径存在：① 变宽 transform lane 映射疑点（潜在正确性缺陷）② 逐 lane 标量访存 + vec::get/set（应使用已支持的 gather/scatter + masked load_convert/store_convert）③ chunk 宽度约束未算内存侧。
- 约束：不牺牲任何运行时性能（bf16 对内联策略敏感，实测 ±3% 内为验收线）；Release 测试保留全保真强制内联；Debug/Release 测试分层保持现状。

## Workstream 0：transform 正确性修复（先行，独立小改动）

**W0.1 变宽 transform lane 映射验证与修复**
- `load/store_transform_chunks`（DataAccess.h:581-701）的记账 `root_lane = lane_begin + lane`、`chunk_lanes = size(Rebind<TIn, ChunkTag>)`、`context.subspan(lane_begin, chunk_lanes)` 隐含等宽假设；TIn/TOut 与 compute 元素宽度不同时 Rebind 改变 lane 数，映射错位。
- 先在 `tests/tensor/TransformTest.cpp` 写复现用例（变宽 VecTransform，如 fp32→fp16 / fp16→fp32，构造根 tag 下不可表示、必须走 chunk 的场景），确认是否真实出错；若出错则定义显式宽度换算的 lane 映射并修复。

**W0.2 chunk 宽度约束纳入内存侧**
- `can_transform_chunk`（DataAccess.h:535）目前只验证 TransformIn/OutTag 可表示性；补充内存侧 tag（M 元素 × chunk lane 数）的可表示性约束，为 W2 的向量化落地扫清障碍；约束不满足时继续减半。

交付：2 个小 PR（或合一），全部现有测试 + 新增用例通过。

## Workstream 1：Request 体系（全选项面，按族分 4 个 PR）

命名与放置：新建 `include/vecops/vec/Request.h`（`vecops::vec` 顶层：`enum class Active/Addressing/Populate` + Request 模板），`details/Request.h`（resolve 函数族，唯一解析点）。原则：**种类轴进模板参数（enum + 现有 mem::/cvt:: tag 类型），数值轴进字段（stride/count/mask 向量/indices/merge 值）**，使数值组合不再繁殖实例化。SVE 约束：Vec/Mask 作命名成员（clang 合法），不做 sizeof/tuple/数组。

**W1.a（PR-1）内存族先行**：LoadRequest / StoreRequest / PrefetchRequest
- `load/store/load_convert/store_convert/prefetch` 增加 Request 重载；variadic 入口改为 `resolve_* + 转发`（行为等价，ConversionMatrixTest 守护）。
- 下游统一：`GenericImpl/execute_word` 及 x86/SVE/scalar 三后端签名改为收 Request，删除 LoadOp/StoreOp 的 4 个 call 重载结构；后端从 Request 类型轴折出 constexpr bool（如 aligned/non_temporal），不再层层转发 Alignment/Temporality 独立类型参数。

**W1.b（PR-2）tensor 层接入**：DataAccess 的 `load_memory/store_memory` 直接构造 Request，删除 `non_address_options/apply_inline/find_option` 转发体操；`InputAccessPolicy` 改为组装 Request 的类型轴而非拆散传递；随后删除 `execute_load_options/execute_store_options` 中间层。此 PR 预期拿到编译时间的主要收益。

**W1.c（PR-3）convert / math / reduction**：纯类型轴（cvt::Ordered/Saturate/Lane、math accuracy、reduction 的 masked/unmasked 单轴）Request 化，统一签名形态；收益以一致性为主。

**W1.d（PR-4）元素级运算**：arithmetic(26)/bit(27)/comparison(16) 入口约 69 个，共用两轴（Active/Populate）Request；逐族机械迁移。

每个 PR 验收：全部测试通过；LayerNormBench/SoftmaxBench 中位数在噪声内且 bf16 专项 ±3%；单 combo 探针 IR 行数与 LayerNormTest 编译时间记录对比（预期 W1.b 后 gcc 244s → ≤160s，实测校准）。

## Workstream 2：transform 向量化（依赖 W1.a/W1.b，排在其后）

- **W2.1** chunk 递归携带向量：mask/index/merge 向量随 tag 减半用 `vec::lower/upper` 同步分裂，递归以 Request/子向量传递，替代标量 lane_begin 记账。
- **W2.2** chunk 落地向量化：每 chunk 用 `load_convert(TransformInTag, ptr, strided(s)|indexed(idx), masked(m)|first(n))` 整块取数（vec 层已原生支持 gather/scatter），transform 每 chunk 调用一次，输出侧 `vec::convert` 回根域。
- **W2.3** 逐 lane 机器收缩：`lane_is_active/logical_lane_offset/inactive_scalar` 的循环用途消失后，仅保留显式命名的 `scalar_transform_fallback`（病态宽度、chunk 砍到最小仍不可表示时），加文档与注释。
- **W2.4**（低优先）`prefetch_tensor` 的逐 lane 地址枚举（DataAccess.h:855-900）同模式向量化或简化。

## Workstream 3：编译时间基础设施（随时可做，W3.1 立即见效）

- **W3.1** 重测试 TU 拆分：LayerNormTest.cpp 按 dtype 拆 4 个 TU；ConversionMemoryMatrixTest.cpp（gcc 398s）同样处理。CMake 的 add_multiarch_executable 已支持多 FILES，ninja 并行后墙钟 ÷4，覆盖率不变。
- **W3.2** 编译时间回归守护：脚本化三个指标（单 combo 探针 O0 IR 行数、LayerNormTest TU 计时、clang -ftime-trace 实例化数趋势），纳入 CI 或本地检查；gcc 13 的 -ftime-report 对本库 ICE，统一用 clang 侧指标。
- **W3.3** 开发迭代指引（文档）：本地迭代优先 clang（同文件 2.6x），ccache 配置说明。
- 明确不做：always_inline 降级（Release 测试的优化冒烟价值优先）。

## 验证环境

- 本地（x86 Sapphire Rapids）：gcc 13.3 + spack clang 19.1.3，全部测试 + bench。
- 远程 920f-4（SVE）：W1.a/W1.b/W2 完成后按 AGENTS.md 工作流 rsync 同步验证 SVE 路径（Request 的 sizeless 命名成员约束、sve 后端统一签名），显式指定编译器。
